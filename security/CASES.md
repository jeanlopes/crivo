# Cases — incidents and what they teach

Real incidents, each reduced to its root cause and linked to the controls that would have stopped it or shrunk it. Figures are the publicly reported ones and are approximate. The point is the mechanism, not the headline: almost every case below is a control from this catalogue that was missing, and none of them required an exotic attacker.

Kept current by the quarterly catalogue review (P11). A new case enters when it teaches something the list does not already teach.

## Injection and the browser

| Year | Case | Root cause | Controls |
|---|---|---|---|
| 2005 | **MySpace "Samy" worm** | Stored XSS in profile pages; the script added its author as a friend of every visitor and copied itself — over a million profiles in about a day. | SEC-016, SEC-018, SEC-020 |
| 2008 | **Heartland Payment Systems** | SQL injection in a web application was the entry point to a network that processed card payments; ~130 million cards. | SEC-001, SEC-134 |
| 2015 | **TalkTalk** | SQL injection in legacy web pages inherited from an acquisition; ~157 000 customers. The pages were not in anyone's inventory. | SEC-001, SEC-114 |
| 2016 | **ImageTragick** (CVE-2016-3714) | ImageMagick executed shell commands embedded in crafted image files; every "upload a picture" feature became remote code execution. | SEC-123 |
| 2016 / 2019 | **Stack Overflow; Cloudflare** | One regular expression with catastrophic backtracking took each down — Stack Overflow for 34 minutes, Cloudflare's global network for about half an hour. | SEC-012 |
| 2018 | **British Airways (Magecart)** | 22 lines added to a JavaScript file on the payment page sent card details to an attacker's domain for two weeks; ~400 000 customers; £20 million fine from the ICO. | SEC-029, SEC-020 |
| 2019 | **Capital One** | SSRF through a misconfigured WAF reached the EC2 metadata service (IMDSv1) and obtained credentials of an over-privileged role; ~100 million people. | SEC-013, SEC-109, SEC-064 |
| 2023 | **MOVEit Transfer** (CVE-2023-34362) | A SQL injection zero-day in a file-transfer product, mass-exploited by the Cl0p group; thousands of organisations and tens of millions of people. SQL injection is not a solved problem. | SEC-001, SEC-095, SEC-117 |
| 2024 | **polyfill.io** | A popular CDN domain changed hands; the new owner served malicious redirects to more than 100 000 sites that loaded the script. | SEC-029 |
| 2025 | **Next.js middleware bypass** (CVE-2025-29927) and **React Server Components RCE** (CVE-2025-55182) | A request header made Next.js skip middleware — including authentication in middleware; later a deserialization flaw in the RSC protocol gave unauthenticated remote code execution. | SEC-034, SEC-095 |

## What the cases have in common

1. **Most breaches start with something known.** Stolen or reused credentials without MFA, and vulnerabilities with published fixes. Domains 3 and 8 carry the highest return per hour of effort.
2. **SaaS data leaks are authorization bugs.** Optus, First American, Parler, Peloton, the RLS apps: the code worked as written; nobody wrote down who must not see what. The authorization matrix (SEC-062) exists for this.
3. **The browser is part of the supply chain.** British Airways, polyfill.io and the 2025 npm compromise all ran attacker code inside legitimate pages. CSP and SRI are cheap relative to that.
4. **Detection time sets the size.** Equifax's 76 days, Heartland's months. Logs nobody reads do not count (SEC-134).
5. **Availability attacks are mostly absorbed at the edge, and mostly caused by code.** The famous DDoS records were survived by providers; the outages people remember came from one regex, one unbounded query, one endpoint with no limit.
