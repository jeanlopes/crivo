# Domain 10 — Files and uploads

An upload feature accepts an attacker-chosen blob, stores it, processes it with complex parsers, and serves it back to other users. Each of those four steps has its own class of attack.

---

### SEC-120 · Validate uploads by content, type allow-list and size
`ASVS:V5` `CWE-434` · verify: test · severity: high

Check the magic bytes against an allow-list of the formats the feature needs; ignore the file extension and the client's `Content-Type`; enforce a maximum size before reading the whole body; cap the number of files per request and per user.

### SEC-121 · Store uploads away from code and under generated names
`ASVS:V5` `CWE-434` `CWE-22` · verify: adversary, config · severity: high

Object storage or a directory outside the web root and outside any path the server executes; file names generated by the server, the original name kept only as metadata and sanitized when displayed. A `.php`, `.jsp` or `.html` saved where the server executes or serves it as-is is remote code execution or stored XSS.

### SEC-122 · Serve user files from a sandbox origin
`ASVS:V5` `ASVS:V3` `CWE-79` · verify: headers · severity: high

A separate registrable domain (for example `usercontent-batuvia.com`, not a subdomain of the app), `Content-Disposition: attachment` for anything not meant to render, `X-Content-Type-Options: nosniff`, and `Content-Security-Policy: sandbox`. SVG and HTML are active content: served from the app origin they run script with the user's session.

### SEC-123 · Process untrusted files in isolation with patched parsers
`ASVS:V5` `CWE-400` `CWE-20` · verify: adversary · severity: high

Image, PDF, video and office-document libraries are large parsers with long CVE histories (ImageTragick, 2016, turned an image upload into remote code execution). Run them in isolated workers with CPU, memory and time limits and without network or credentials; strip metadata such as GPS coordinates before storing or serving images.

### SEC-124 · Extract archives defensively
`ASVS:V5` `CWE-22` `CWE-409` · verify: test · severity: high

Reject entries whose resolved path escapes the target directory (zip slip), symlinks, and absolute paths; cap entry count, per-file size and total uncompressed size (zip bombs).

### SEC-125 · Scan files that other users will download
`ASVS:V5` `CWE-434` · verify: config · severity: medium

Where one user's upload reaches another user — shared documents, attachments, marketplace files — scan for malware before making the file available, and quarantine on detection.
